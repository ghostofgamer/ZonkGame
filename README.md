# Зонк: Кости Фортуны

Игра в кости «Зонк» (в других странах Farkle) для Яндекс Игр, Игр ВКонтакте и RuStore.
Создана из шаблона GameBase: интеграция площадок, сохранения, реклама, покупки, язык и качество графики
взяты из шаблона (`Assets/Scripts`, сборки `Base.*`), код игры в `Assets/ZonkContent` (сборка `Zonk`).

| Что | Значение |
|---|---|
| Название | «Зонк: Кости Фортуны» (`ProjectIdentity.ProductName`) |
| Android-пакет | `ru.ghostofgamer.zonk`, после публикации в RuStore не меняется |
| Игры ВКонтакте | ID 54765957 (`vk-hosting-config.json`) |
| Код игры | `Assets/ZonkContent`, пространство имён `Zonk`, инсталлер `ZonkInstaller` в `ProjectContext` |

Структура, стек и правила: [AGENTS.md](AGENTS.md). Ниже описание игры, затем шаблона: оно остаётся актуальным и для игры.

## Игра

**Запуск в редакторе.** Один раз: меню `Zonk/Setup/Build Everything`. Генератор создаёт недостающие материалы,
префабы-заглушки, весь контент, сцены `ZonkContent/Scenes/Bootstrap` и `Table`, проставляет ссылки в `ZonkInstaller`
и Build Settings, затем проверяет контент. Дальше открыть `Bootstrap.unity` и нажать Play.
Уже созданные ассеты генератор не трогает, сцены пересоздаёт (после вопроса).

**Режимы.** Игра вдвоём на одном экране (цель 1000–10000, у каждого свои кости и скин, бесплатно, без наград),
кампания (главы: обычные соперники, затем босс с особым правилом; энергия за партию; награды: монеты, особые кости,
предметы). Грозные версии боссов (после трёх звёзд у босса). «Бесконечный забег» (рогалик: этажи со случайными
соперниками, находки после побед, сердца, рекорд) и башня (30 этажей с рубежами, расширяется новыми этажами). Уровень игрока: опыт за каждую партию против соперника, за проигрыш тоже; награды за уровни, башня и забег открываются с уровня. Задания на день и неделю, мастерство особых костей, сохранённые наборы костей. Онлайн позже: партия уже устроена так, что сетевой игрок станет ещё одним `IPlayerController`.

**Сцены.** `Bootstrap` (логотип, ждёт SDK и сохранение) → `Table` (одна сцена: меню, магазин, партия
отличаются ракурсом камеры и экраном UI, без загрузок между ними).

| Этаж башни | строка в `Configs/Modes/Tower.asset`: соперник, цель, правила этажа, награда за первое прохождение. Новые этажи — в конец списка: игроки продолжат с рубежа |

| Задание дня или недели | ассет `Zonk/Quest` в `Configs/Quests/Daily` или `Weekly`: период, вес, цель, награды, по желанию условия выдачи, группа и флаг «обязательное». **Задания: как расширять.** Всё новое добавляется ассетом или одним классом, код сервиса не меняется.

| Что | Как |
|---|---|
| Задание на то, что игра уже сообщает | ассет `Zonk/Quest` с готовой целью: партии, победы (можно только боссы), победа с костью, без особых костей, очки, крупный ход, горячие кости, комбинация по категории, реклама, дни захода, дневные задания, событие по тегу |
| Задание на новое действие без нового класса | в коде в месте действия `IQuestService.Report(QuestEvent.CustomEvent("тег"))`, в ассете цель `CustomEventGoal` с этим тегом. Уже сообщается: `shop_acquired` (предмет получен в магазине), `manual_roll` (бросок своей рукой, кроме игры вдвоём) |
| Новый вид цели | наследник `QuestGoal` (`Progress(QuestEvent)`, по желанию `IsAvailable`, `TextArgKey`, `OffersAdButton`) |
| Когда задание можно выдавать | условия `QuestConfig.Conditions`: реклама доступна, есть предмет, глава открыта, соперник побеждён. Новое условие — наследник `QuestCondition`, новое знание об игроке — поле `QuestContext` |
| Задание в каждом наборе | флаг `Guaranteed` (так сделано «Посмотрите рекламу» на день и на неделю) |
| Похожие задания не вместе | одинаковая `Group` (так сделаны «Победите с костью …»): в наборе не больше одного из группы |
| Кнопка действия прямо в строке задания | `QuestGoal.OffersAdButton` (реклама); окно показывает её вместо «Забрать», пока задание не выполнено |

**Экономика.** Окно `Zonk/Economy Report` считает по настоящим ассетам: сколько стоит всё за монеты, что дарит кампания,
сколько монет в день получают разные игроки (кампания, повторные победы с удвоением, задания, мастерство) и за сколько
дней они всё купят (модель `EconomyModel` в ядре). Цель: первая покупка в первые дни, активный игрок докупает то, что
не дарит кампания, за 2–3 недели, случайный — за 1,5–2 месяца. Проверять после любых изменений цен, наград и нового контента.
Косметику дарят только боссы, обычные соперники дают монеты и особые кости.

Реестр контента собирается сам. Перед сборкой игры валидатор (`Zonk/Content/Validate`) проверяет ID, ссылки,
ключи локализации, соглашение граней у мешей костей и `Mouth` у стаканов: ошибка останавливает сборку.

**Соглашение для моделей костей:** грани 1 = +Y, 6 = −Y, 2 = +Z, 5 = −Z, 3 = +X, 4 = −X; UV-атлас 3×2
(сверху 1 2 3, снизу 4 5 6); точки в текстуре. Тогда любой скин подходит к любой кости. У стакана дочерний объект `Mouth` в горле.

**Тексты.** Все строки в `ZonkContent/Localization/Texts.csv` (`key,ru,en,tr,es,pt,de,fr`). Бесплатный процесс для всех игр:
Google Таблица (можно черновой перевод формулой `=GOOGLETRANSLATE(B2;"ru";"en")`, затем вычитать) →
«Файл → Поделиться → Опубликовать в интернете → лист → CSV» → ссылку вставить в `ZonkContent/Localization/TextsSheet.asset` →
меню `Base/Localization/Download Sheets`. Скачанный файл проверяется до записи: сломанный CSV рабочий не затирает.

**Общий слой игры** (`Base.Services`, подключается `GameServicesInstaller`), одинаковый во всех играх:

- `ISaveStore`: сохранение по разделам с номером версии и миграциями. Если облако не прочиталось,
  запись в облако выключается до конца сессии, чтобы не затереть прогресс.
- `IEntitlements`: права игрока, например `no_ads`. Игра спрашивает право, а не покупку.
- `IPurchaseFlow`: покупка, выдача, восстановление при запуске, защита от двойной выдачи расходуемых товаров.
- `IRewardService`: награда «за рекламу или бесплатно» по правилам.
- `IInterstitialService`: interstitial по поводу («партия закончилась»), частота в одном месте.
- `AdPauseController`: пауза и выключение звука на время рекламы и при потере фокуса.
- `IQualityService`: уровень графики по типу устройства. `ILocalization`: язык из SDK, ru и en.
- `IHapticsService`: короткая вибрация на Android (в браузере игра во фрейме чужого домена, там вибрация запрещена). Включена ли она у игрока — решает игра.

## Задачи на подумать

### Аналитика (AppMetrica, бесплатно)

Цель: видеть, кто что прошёл, где игроки уходят, что покупают и смотрят, и по этим данным развивать игру.

**Сделано (30.09):** AppMetrica 6.10.0 в RuStore-сборке, код игры отправляет события через `IAnalytics` по «папкам».
Отправляются: старт игры (`session`, тестовая копия — в `test`) и шаги обучения (`tutorial`). Все события игры —
в одном месте, `Runtime/Analytics/GameAnalytics.cs`, там же схема папок. Остальные категории ниже — по одной, когда дойдём.

**Как читать в AppMetrica.** Отчёт «События» → имя события (верхняя папка) → «Параметры событий»: дерево,
каждый уровень раскрывается щелчком, у каждого узла — сколько раз и сколько игроков.

```csharp
// campaign → win → chapter_1 → semenych → turns: 9
analytics.Event("campaign").Path("win", "chapter_1", "semenych").Param("turns", 9).Send();
// tutorial → step → ChooseDice (последняя папка без Param становится значением)
analytics.Track("tutorial", "step", "ChooseDice");
// одно событие, две ветки: ads → rewarded → double_reward / energy → result
analytics.Event("ads").Path("rewarded", "double_reward").Param("result", "completed").Send();
analytics.SetUserProperty("chapter", 3);   // свойство игрока: срез для всех отчётов
```

Правила: имена латиницей в snake_case; в значениях ID контента (`semenych`, `die_lucky`), не названия на языке;
не больше 5 уровней вместе с Param (ограничение AppMetrica, лишнее обрезается); что сравнивать — делать папкой
(`Path`), что измерять — значением (`Param`). В редакторе и отладочной сборке события пишутся в консоль
с префиксом `[Analytics]`.

**Осталось решить:**
- Браузер (Яндекс Игры, VK): у AppMetrica нет веб-SDK для Unity. Брать Яндекс Метрику (цели и параметры визитов
  через JS, как наш мост SDK) — это будет `IAnalyticsService` для Яндекса и VK; код игры не меняется.
  Посмотреть и встроенную статистику Консоли Яндекс Игр. Условия площадок по сбору данных — перечитать.
- Политика конфиденциальности для RuStore должна упоминать AppMetrica.
- События не разбросаны по коду: одно место на категорию (слушатели уже существующих событий — награды за рекламу
  `IRewardService.Completed`, покупки `IPurchaseFlow.Delivered`, задания, мастерство, итоги партии).

**Категории событий («папки» в отчётах) — черновик:**

| Категория | События и параметры |
|---|---|
| `session` | запуск (площадка, язык, уровень качества, номер дня с установки), выход |
| `tutorial` | каждый шаг обучения (`TutorialTrigger`) — где новички отваливаются |
| `campaign` | начало партии (соперник, глава, ставка, особые кости), победа / поражение / сдача (счёт, ходы, Зонки, звёзды) |
| `ads` | реклама за награду по месту (`placement`: удвоение, энергия, магазин, меню, задание) и результат (досмотрел / закрыл / нет рекламы); межстраничная реклама (показана / пропущена по частоте) |
| `purchase` | открытие товара, начало покупки, успех / отмена по `ProductId`, стартовый набор, «Без рекламы» |
| `economy` | получение и трата монет и энергии с источником (победа, задание, реклама, покупка, ставка) |
| `shop` | просмотр вкладки, выбор предмета, получение (способ: монеты / реклама / деньги / награда) |
| `quests` | выдано, выполнено, забрано, заменено за рекламу |
| `progress` | новая глава, новый уровень мастерства кости, новая звезда, место в рекордах |
| `settings` | смена языка, звук, скорость |

**Свойства игрока (для разрезов):** дошёл до главы, всего звёзд, платящий или нет, «Без рекламы», день с установки,
площадка.

**Какие вопросы должны закрывать отчёты:** воронка обучения и первой партии; на каком сопернике уходят; удержание
1 / 7 / 30 дней; сколько реклам в день и где; конверсия в первую покупку и что покупают; хватает ли монет
(баланс `Zonk/Economy Report` против реальности).

### 2026-09-30 (Зонк, бросок своей рукой)

- Кости можно бросить своей рукой: зажать свой стакан мышью или пальцем, потрясти и толкнуть к столу. Кнопка

### 2026-10-02 (уровень игрока)
