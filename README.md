# Зонк: Кости Фортуны

Игра в кости «Зонк» (в других странах Farkle) для Яндекс Игр, Игр ВКонтакте и RuStore.
Создана из шаблона GameBase: интеграция площадок, сохранения, реклама, покупки, язык и качество графики
взяты из шаблона (`Assets/Scripts`, сборки `Base.*`), код игры в `Assets/ZonkContent` (сборка `Zonk`).

| Что | Значение |
|---|---|
| Название | «Зонк: Кости Фортуны» (`ProjectIdentity.ProductName`) |
| Android-пакет | `ru.ghostofgamer.zonk`, после публикации в RuStore не меняется |
| Игры ВКонтакте | ID 54765957 (`vk-hosting-config.json`) |
| Код игры | `Assets/ZonkContent`, пространство имён `Zonk`, инсталлер `ZonkInstaller` в `ProjectContext` |

Структура, стек и правила: [AGENTS.md](AGENTS.md). Ниже описание игры, затем шаблона: оно остаётся актуальным и для игры.

## Игра

**Запуск в редакторе.** Один раз: меню `Zonk/Setup/Build Everything`. Генератор создаёт недостающие материалы,
префабы-заглушки, весь контент, сцены `ZonkContent/Scenes/Bootstrap` и `Table`, проставляет ссылки в `ZonkInstaller`
и Build Settings, затем проверяет контент. Дальше открыть `Bootstrap.unity` и нажать Play.
Уже созданные ассеты генератор не трогает, сцены пересоздаёт (после вопроса).

**Режимы.** Игра вдвоём на одном экране (цель 1000–10000, у каждого свои кости и скин, бесплатно, без наград),
кампания (главы: обычные соперники, затем босс с особым правилом; энергия за партию; награды: монеты, особые кости,
предметы). Задания на день и неделю, мастерство особых костей, сохранённые наборы костей. Онлайн позже: партия уже устроена так, что сетевой игрок станет ещё одним `IPlayerController`.

**Сцены.** `Bootstrap` (логотип, ждёт SDK и сохранение) → `Table` (одна сцена: меню, магазин, партия
отличаются ракурсом камеры и экраном UI, без загрузок между ними).

**Как добавить контент (без кода):**

| Что | Как |
|---|---|
| Предмет косметики | ассет `Zonk/Cosmetic Item`: слот, Payload (префаб, материал или меш + материал), цена. Появится в магазине |
| Новая деталь интерьера | ассет `Zonk/Cosmetic Slot` + в сцене `CosmeticAnchor` с ID слота и `CameraShot` с ID из `CameraShotId` |
| Особая кость | ассет `Zonk/Die`: веса граней, цвет метки. Проверить в `Zonk/Balance Simulator` (полоса 47–53%) |
| Соперник | ассет `Zonk/Opponent`: профиль ИИ, реакции, кости (у обычных 0–3 особые, у боссов от 3: `GameConfig.OpponentMaxSpecialDice` / `BossMinSpecialDice`, проверяет валидатор), награды; босс — плюс модификатор и `RuleKey` |
| Глава | ассет `Zonk/Chapter`: локация, соперники по порядку (последний — босс), сюжет |
| Стиль появления окна | ассет `Zonk/UI/Transition` (набор эффектов: прозрачность, прилёт с края, сдвиг, масштаб, поворот, толчок, тряска, по очереди). Готовые — в `Configs/Ui/Transitions` |
| Окно UI | префаб в `Prefabs/UI` с компонентом-наследником `UiWindow`, стили появления и скрытия — поля префаба; в `UiConfig.Windows` попадает само, открывать `IUiService.OpenAsync<T>()` |
| Задание дня или недели | ассет `Zonk/Quest` в `Configs/Quests/Daily` или `Weekly`: период, вес, цель, награды, по желанию условия выдачи, группа и флаг «обязательное». Текст: `{0}` — сколько нужно, `{1}` — название из цели (кость). Сколько заданий в день и неделю — `GameConfig`. Подробнее — «Задания: как расширять» ниже |
| Уровень мастерства | строка в `GameConfig.MasteryLevels` (очки, цвет, свечение, награды) и материал уровня в `DieConfig.MasteryLooks` каждой особой кости |
| Подсказка загрузки | строка `tip.N` в `Texts.csv` и ключ в `UiConfig.TipKeys` |
| Язык | столбец с кодом языка в `Texts.csv` (Google Таблица): язык включается сам |
| Стиль броска | ассет `Zonk/Roll Style` (диапазоны тряски, наклона, силы и разброса) и предмет слота «Бросок» с `RollStylePayload`: появится в магазине. У соперника — `OpponentConfig.RollStyle` |
| Страница правил или пример комбинации | строка в `Configs/Ui/RulesBook.asset` и ключи в `Texts.csv`; очки примера считают правила, выключенная комбинация пропадает из книги сама |
| Новое правило босса, тактика ИИ, комбинация, награда, цель задания | один класс-наследник (`MatchModifier`, `AiRiskPolicy`, `ScoringRule`, `Reward`, `QuestGoal`), он появится в списке в инспекторе |

**Задания: как расширять.** Всё новое добавляется ассетом или одним классом, код сервиса не меняется.

| Что | Как |
|---|---|
| Задание на то, что игра уже сообщает | ассет `Zonk/Quest` с готовой целью: партии, победы (можно только боссы), победа с костью, без особых костей, очки, крупный ход, горячие кости, комбинация по категории, реклама, дни захода, дневные задания, событие по тегу |
| Задание на новое действие без нового класса | в коде в месте действия `IQuestService.Report(QuestEvent.CustomEvent("тег"))`, в ассете цель `CustomEventGoal` с этим тегом. Уже сообщается: `shop_acquired` (предмет получен в магазине) |
| Новый вид цели | наследник `QuestGoal` (`Progress(QuestEvent)`, по желанию `IsAvailable`, `TextArgKey`, `OffersAdButton`) |
| Когда задание можно выдавать | условия `QuestConfig.Conditions`: реклама доступна, есть предмет, глава открыта, соперник побеждён. Новое условие — наследник `QuestCondition`, новое знание об игроке — поле `QuestContext` |
| Задание в каждом наборе | флаг `Guaranteed` (так сделано «Посмотрите рекламу» на день и на неделю) |
| Похожие задания не вместе | одинаковая `Group` (так сделаны «Победите с костью …»): в наборе не больше одного из группы |
| Кнопка действия прямо в строке задания | `QuestGoal.OffersAdButton` (реклама); окно показывает её вместо «Забрать», пока задание не выполнено |

**Экономика.** Окно `Zonk/Economy Report` считает по настоящим ассетам: сколько стоит всё за монеты, что дарит кампания,
сколько монет в день получают разные игроки (кампания, повторные победы с удвоением, задания, мастерство) и за сколько
дней они всё купят (модель `EconomyModel` в ядре). Цель: первая покупка в первые дни, активный игрок докупает то, что
не дарит кампания, за 2–3 недели, случайный — за 1,5–2 месяца. Проверять после любых изменений цен, наград и нового контента.
Косметику дарят только боссы, обычные соперники дают монеты и особые кости.

Реестр контента собирается сам. Перед сборкой игры валидатор (`Zonk/Content/Validate`) проверяет ID, ссылки,
ключи локализации, соглашение граней у мешей костей и `Mouth` у стаканов: ошибка останавливает сборку.

**Соглашение для моделей костей:** грани 1 = +Y, 6 = −Y, 2 = +Z, 5 = −Z, 3 = +X, 4 = −X; UV-атлас 3×2
(сверху 1 2 3, снизу 4 5 6); точки в текстуре. Тогда любой скин подходит к любой кости. У стакана дочерний объект `Mouth` в горле.

**Тексты.** Все строки в `ZonkContent/Localization/Texts.csv` (`key,ru,en,tr,es,pt,de,fr`). Бесплатный процесс для всех игр:
Google Таблица (можно черновой перевод формулой `=GOOGLETRANSLATE(B2;"ru";"en")`, затем вычитать) →
«Файл → Поделиться → Опубликовать в интернете → лист → CSV» → ссылку вставить в `ZonkContent/Localization/TextsSheet.asset` →
меню `Base/Localization/Download Sheets`. Скачанный файл проверяется до записи: сломанный CSV рабочий не затирает.

**Общий слой игры** (`Base.Services`, подключается `GameServicesInstaller`), одинаковый во всех играх:

- `ISaveStore`: сохранение по разделам с номером версии и миграциями. Если облако не прочиталось,
  запись в облако выключается до конца сессии, чтобы не затереть прогресс.
- `IEntitlements`: права игрока, например `no_ads`. Игра спрашивает право, а не покупку.
- `IPurchaseFlow`: покупка, выдача, восстановление при запуске, защита от двойной выдачи расходуемых товаров.
- `IRewardService`: награда «за рекламу или бесплатно» по правилам.
- `IInterstitialService`: interstitial по поводу («партия закончилась»), частота в одном месте.
- `AdPauseController`: пауза и выключение звука на время рекламы и при потере фокуса.
- `IQualityService`: уровень графики по типу устройства. `ILocalization`: язык из SDK, ru и en.

## Новая игра из шаблона

**Один раз, для самого шаблона:** на GitHub переименовать репозиторий (например, в `GameBase`)
и в Settings поставить галочку **Template repository**. GitHub Desktop подхватит новое имя сам.

**Для каждой новой игры:**

1. GitHub → репозиторий шаблона → **Use this template** → новый репозиторий с именем игры. Склонировать в GitHub Desktop.
2. Открыть в Unity 6000.3.23f1 (первый импорт долгий).
3. Поменять то, что своё у игры:

| Файл | Что поменять |
|---|---|
| `Assets/Scripts/Editor/ProjectIdentity.cs` | `ProductName` (название, можно по-русски), `BuildFileName` (имя APK латиницей), `AndroidPackage` (`ru.ghostofgamer.<игра>`, **после публикации в RuStore не меняется никогда**) |
| `vk-hosting-config.json` | `app_id` игры в VK (создать игру на dev.vk.com). Сейчас там ID «Зонк: Кости Фортуны» |
| `Assets/Scripts/Services/Monetization/MonetizationConfig.cs` | товары (ID как в консоли площадки), частота interstitial, правила наград |
| `Assets/Scripts/Platform/RuStore/RuStoreAdUnits.cs` | свои рекламные блоки из partner.yandex.ru перед публикацией (для тестов работают демо) |
| `<Название>Content/Localization/*.csv` | тексты игры (`key,ru,en`), источник — Google Таблица, см. раздел «Игра». `LocalizationTable` шаблона оставить как есть |
| Project Settings → Player | иконка, заставка, ориентация экрана |
| `README.md`, `AGENTS.md` | шапка README про игру; в AGENTS.md добавить раздел об игре, правила шаблона оставить |

4. Код игры: папка `Assets/<Название>Content/Scripts/`, в ней asmdef `<Название>` со ссылками на `Base.Core`, `Base.Services`,
   `Base.Platform.Abstractions`, `UniTask`, `Zenject`. Сборку добавить в `Assets/link.xml` с `preserve="all"`.
5. Zenject: сервисы игры, которые живут всё время, и миграции сохранений (`ISaveMigration`) биндятся в своём
   `MonoInstaller`, добавленном в список Mono Installers в `Assets/Resources/ProjectContext.prefab`.
   Сервисы одной сцены: `SceneContext` в сцене со своим инсталлером.
6. Build Settings: первой поставить сцену игры. `PlatformTest` оставить в проекте для проверки площадок, из сборки убрать.
7. В консолях площадок завести лидерборды и товары с теми же ID, что в коде.
8. Меню `Base/Platform/<площадка>`, затем `Base/Build/...`.

Исправления, сделанные в игре и касающиеся шаблона (`Assets/Scripts`), переносить в шаблон руками, и наоборот.
Когда игр станет три и больше, платформенный слой стоит вынести в UPM-пакет, чтобы исправления приходили обновлением.

**Зонк** (этот репозиторий): первая игра из шаблона, пакет `ru.ghostofgamer.zonk`, VK ID 54765957.

### 2026-09-29 (Зонк, защита ручных правок UI от генератора)

- Метка `ZonkLocked` на префабе окна или сцене: генератор её не удаляет и не пересоздаёт (`Rebuild UI Prefabs`,
  `Build Everything`, `Rebuild Scenes`), в консоли пишет, что пропустил. Поставить или снять: выделить ассет
  в Project → `Zonk/Setup/Lock or Unlock Selected` (или ПКМ → Zonk). Список: `Zonk/Setup/Show Locked`.
- `Zonk/Setup/Rebuild Selected UI Prefabs`: пересоздать только выделенные окна, сцены не трогаются.
- Правило: новые элементы окон в коде проверяются на null, чтобы заблокированный (старый) префаб работал;
  что добавить в него руками — пишется в журнале.
- Снимки окон (`ZonkSetup.Snapshots`): свой вид окна сохраняется `Zonk/Setup/Save UI Snapshot` (выделенные окна
  или все), и `Rebuild UI Prefabs` / `Rebuild Selected UI Prefabs` возвращают окно к нему, а не к вёрстке генератора.
  Вернуть вручную: `Zonk/Setup/Restore UI from Snapshots`. Отказаться от своего вида: `Forget UI Snapshot of Selected`.
  Снимки лежат в `UiSnapshots/` в корне проекта (вне Assets, в сборку не попадают, хранятся в git); при
  восстановлении заменяется файл префаба, а .meta остаётся — ссылки на окно не ломаются.
